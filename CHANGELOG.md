## 2026-08-02

### Added
- **Adaptive Skill Rotation** — a new Open Play rotation mode that keeps Beginners playing Beginners and Intermediates playing Intermediates, while still using the same waiting-time/fairness rules every other mode uses. Players are automatically promoted to Intermediate after a configurable number of consecutive wins, and moved back to Beginner after a configurable number of consecutive losses (both default to 3, adjustable in Session Settings) — a facilitator can also move a player between divisions manually at any time, which always takes priority over the automatic promotion/relegation. Within each division, a "Winner vs Winner" preference tries to match players on similar win/loss streaks against each other, without ever creating fixed partnerships or blocking a match from being made. Every promotion, relegation, and manual change is recorded with a timestamp and reason. 43-assertion Node test suite plus the existing 42-assertion Open Play acceptance suite, both green.
- **Smart Queue Management** — a set of facilitator tools for running a busy Open Play queue day-to-day: **Hold Player** temporarily takes someone out of matchmaking (for an injury, a phone call, etc.) without losing their stats or streaks, and **Resume Player** brings them back; **Skip Player** simply sends someone to the back of the waiting line without excluding them from play; **Hold Match** reserves an upcoming pairing so it won't be auto-assigned to a court, and **Resume**/**Cancel** either restore it to its original place in line or dissolve it back into the waiting pool. Every waiting player now shows a live "waiting since" timer and a clear status (Playing / Upcoming / Waiting / Held / Checked Out). The upcoming-match queue is now automatically capped to one less than the number of live courts, so it no longer builds up more pre-paired matches than the session can actually use. 86-assertion Node test suite across two suites, plus the existing acceptance suite, all green.
- **Held Match Activity Logging** — when a held matchup gets automatically dissolved (because one of its players checked out, was substituted, changed skill division, or was otherwise pulled out), the facilitator now sees exactly which match it was and why — both teams' names, the court context, and a plain-language reason — in a small, scannable activity-log card, rather than a generic one-line note.
- **Smart Court Dispatch** — Open Play can now automatically send the next eligible match onto a court the instant one becomes available, with no facilitator click required, and announce it out loud ("Court 3. John and Mike, versus Peter and Carl. Please proceed to Court 3.") using the browser's built-in text-to-speech — no external service needed. A dispatched court shows "Calling Players…" while the announcement plays, then switches to Playing automatically once it finishes (or after a short configurable delay if announcements are off) — or waits for the facilitator to press Start Match, if the new Auto Start Match setting is turned off. New Session Settings let facilitators turn Auto-fill Courts, Auto Start Match, and Voice Announcements on or off independently, and adjust the announcement's delay, volume, voice, and speed. A Repeat Announcement button is available on any dispatched or in-progress court. Every dispatch and announcement is recorded in the same activity log Held Match Logging introduced. 34-assertion Node test suite plus the existing acceptance and queue-management suites, all green.

Browser-verified end to end — court CRUD, Quick Guest Booking creating a real player record, live availability narrowing, conflict detection (double-booking + invalid time range) with friendly messages, calendar click-to-create/click-to-edit, booking status transitions, and a live Open Play session confirming a reserved court is hard-blocked from both assignment paths while an unreserved court behaves normally — zero console errors

## 2026-07-16 (later)

### Added
- New pluggable matchmaking architecture (Strategy pattern): `src/engines/RotationEngine.js` defines the interface, `src/engines/BalancedRotationEngine.js` is the concrete "Balanced Beginner+Intermediate Rotation" implementation, replacing the ad hoc pairing helpers previously in `lib/utils.js`. Scores candidate pairings by partner/opponent recency (never partnered: +100, partnered last round: -100, partnered within 2 rounds: -75, partnered often: -50; symmetric opponent-avoidance scoring), with randomized-restart tie-breaking so greedy selection doesn't paint itself into a forced bad pairing
- Per-player rotation history: `partnerCounts`/`recentPartnerIds`, `opponentCounts`/`lastOpponentIds`/`recentOpponentIds`, `courtCounts`/`lastCourt`, recorded automatically when a match ends. `state.matchHistory` now logs one record per completed match (round, court, teams, winner, score)
- Scorer view: "Regenerate matchups" — rebuilds every not-locked upcoming matchup from scratch using the current pool of waiting players
- Scorer view: per-matchup "Lock" toggle — protects a matchup from "Regenerate matchups" (everything else, like Fix teams/Substitute, still works on a locked matchup)
- Scorer view: "Waiting players" panel — "Skip" a player (sits out, stays visible, excluded from matchmaking until un-skipped) or "Remove" them from the session entirely (for players not currently on a live court)

### Changed
- Matchmaking now allows a same-skill (beginner+beginner or intermediate+intermediate) team as a last resort, but only when the beginner/intermediate counts are genuinely unequal *and* the organizer explicitly clicks "Regenerate matchups" — the passive, automatic matchup-building that runs after every check-in stays strict (mixed teams only) so a same-skill pairing never gets permanently locked in just because players happened to check in one at a time
- When an odd number of teams would leave one benched, a same-skill fallback team is now always the one held back over a properly mixed team, rather than the two being treated as equally disposable

### Deferred (called out explicitly, not silently dropped)
- No UI to pick a different rotation strategy — only one engine exists; the interface supports adding more (Random Mixer, King of the Court, Winner-Up/Loser-Down, DUPR Rotation, Challenge Court, Round Robin) without changing the rest of the app, but building those specific modes and a picker UI is future work
- No "undo previous round" — ending a match, substituting, or removing a player are all one-way actions
- No dedicated stats screen for partner/opponent frequency or court usage — the history is tracked per-player but not yet surfaced beyond Standings' games/wins/losses/streak
- "Swap two players" / "swap entire teams" are covered by the existing Fix Teams / Substitute controls rather than being separate new features
